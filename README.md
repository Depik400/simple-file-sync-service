# File Sync - Распределенная система синхронизации файлов

Это пример реализации распределенной системы синхронизации файлов на Go с веб-интерфейсом, похожей на rsync, но с поддержкой нескольких серверов в P2P топологии.

## Возможности

- **P2P синхронизация**: Поддержка нескольких серверов в peer-to-peer топологии
- **Веб-интерфейс**: Просмотр файлов, история изменений, статус синхронизации
- **Скачивание файлов**: Возможность скачивать файлы с любого сервера
- **Синхронизация удалений**: Автоматическое удаление файлов на всех серверах
- **История изменений**: SQLite база данных для отслеживания всех изменений
- **Конфигурация**: YAML конфигурация для настройки серверов

## Структура проекта


## Установка и запуск

### 1. Клонирование и установка

```bash
git clone <your-repo-url>
cd file-sync
go mod tidy
go build
```

### 2. Быстрый старт

```bash
# Демонстрация логики синхронизации
make test-sync

# Тест синхронизации в demo режиме
make demo-test

# Полноценные серверы
make run-multi
```

### 2. Запуск серверов

#### Одиночный сервер
```bash
./file-sync
```
Сервер будет доступен по адресу `http://localhost:8081`

#### Мульти-серверное тестирование
```bash
make run-multi
```

Для тестирования запустите серверы в отдельных терминалах:

```bash
# Terminal 1 - Server 1
./file-sync examples/config-server1.yaml

# Terminal 2 - Server 2
./file-sync examples/config-server2.yaml
```

#### Демонстрация логики синхронизации
```bash
make test-sync
```
Показывает, как работает синхронизация файлов без сетевых зависимостей.

#### Демонстрация удалений файлов
```bash
make test-deletions
```
Показывает, как работает синхронизация удаления файлов между серверами.

#### Быстрый тест в demo режиме
```bash
make demo-test
```
Запускает серверы в demo режиме, создает тестовый файл и показывает процесс синхронизации.

#### Готовые конфигурации
- **Server 1**: http://localhost:8090 (P2P: 8090)
- **Server 2**: http://localhost:7071 (P2P: 7071)

Тестовые файлы уже созданы в `examples/sync_data_server1/`

## API Endpoints

### Веб-интерфейс
- `GET /` - Дашборд
- `GET /files` - Браузер файлов
- `GET /history` - История изменений

### REST API
- `GET /api/files` - Список локальных файлов
- `GET /api/files/{server}/{filePath}` - Скачивание файла
- `GET /api/history/{filePath}` - История файла
- `GET /api/changes` - Последние изменения
- `GET /api/servers` - Список серверов
- `GET /api/peers` - Список подключенных пиров

### P2P API
- `POST /sync` - Синхронизационные сообщения
- `GET /files/{filePath}` - Получение файла
- `PUT /files/{filePath}` - Отправка файла
- `GET /health` - Проверка здоровья сервера

```bash
go run main.go config-server1.yaml

go run main.go config-server3.yaml
```

## Использование

1. **Веб-интерфейс**: Откройте браузер и перейдите на `http://localhost:8081`
2. **Просмотр файлов**: Перейдите в раздел "Files" для просмотра и скачивания
3. **История**: Используйте раздел "History" для просмотра изменений файлов
4. **Синхронизация**: Файлы автоматически синхронизируются между серверами

## Архитектура

### Компоненты

- **Config**: Загрузка и управление конфигурацией
- **Database**: SQLite хранилище истории изменений
- **P2P Network**: Коммуникации между серверами
- **File Sync**: Логика синхронизации файлов
- **Web Server**: HTTP сервер с REST API и веб-интерфейсом

### P2P Протокол

Серверы обмениваются сообщениями через HTTP API:
- Heartbeat проверки для обнаружения активных пиров
- Broadcast списков файлов для синхронизации
- Прямой обмен файлами между серверами
